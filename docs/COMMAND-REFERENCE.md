# OMEN BIOS/ACPI 完整命令参考（Complete Command Reference）

> 单文件自包含。整合：协议原理 + SSDT12 反汇编 + 通用命令表 + 本机（8BAB）逐条实测。
> 目标机型：**OMEN by HP Gaming Laptop 16-wf0xxx，主板 8BAB**。
> 其他机型可参考，但**传输方式和可用命令可能不同**（务必先只读探测）。

## 0. ⚠️ 实测副作用提醒

测试写命令会把状态留在硬件里。本次测试**把 EC 留在了手动风扇模式**（风扇固定 6400 RPM，`0x1A` 无法解除）——
**请重启一次电脑**恢复自动控制。写命令前务必先想好"如何恢复"。

## 1. 原理速览（30 秒版）

```
你的程序 → 写入 /proc/acpi/call → acpi_call 内核模块 → ACPI 方法 \_SB.WMID.WMAA → 固件/EC → 返回
```

- HP 在 ACPI 树里塞了私有方法 `\_SB.WMID.WMAA`（Windows 上叫 `hpqBIntM`）。
- Linux 通过内核模块 **`acpi_call`** 暴露的 **`/proc/acpi/call`** 调用它。
- 写入 = 调用，读取 = 取结果。
- 命令打包成一个"信封"（SECU），里面放：命令空间 + 命令类型 + 数据。

### 本机关键事实
- **没有 `WQAA`**，所有命令走 `WMAA`。
- `WMAA` 第 2 个参数是 **mode**（输出缓冲区大小选择器）。
- 成功返回 **`PASS`**（4 字节），失败 `FAIL`。

---

## 2. 调用形式

```
\_SB.WMID.WMAA 0x00 <mode> {SECU 缓冲区}
```

### 2.1 SECU 缓冲区布局

```
偏移   长度  内容
0x00   4    53 45 43 55          "SECU" 签名
0x04   4    Command  u32 小端     命令空间
0x08   4    CommandType u32 小端  低字节=类型，其余 0
0x0C   4    Size     u32 小端     数据长度（≥1）
0x10   N    data                 数据
```

### 2.2 Command 空间（偏移 0x04）

| 值 | 小端字节 | 用途 |
|---|---|---|
| `0x00020008` | `08 00 02 00` | 性能/风扇/温度/系统（最常用） |
| `0x00020009` | `09 00 02 00` | 灯效 |
| `0x00000001` | `01 00 00 00` | Legacy 读（适配器、显卡模式、旧除尘） |
| `0x00000002` | `02 00 00 00` | 写（显卡模式、旧除尘） |

> ⚠️ **必须小端**。`0x00020008` 写成 `08 00 00 02` 会被固件拒绝（返回 FAIL 0x03）。

### 2.3 mode（`WMAA` 第 2 参数）

| mode | 返回总长 | 可用数据 |
|---|---|---|
| `0x01` | 8 | 0 |
| `0x02` | 12 | **4** |
| `0x03` | 136 | **128** |
| `0x04` | 1032 | 1024 |
| `0x05` | 4104 | 4096 |

**规则**：mode 选"能装下该命令返回数据的最小档位"。4 字节→`0x02`，128 字节→`0x03`。
选小了返回 `FAIL 0x05`。

### 2.4 返回格式

```
[0..3]  "PASS"(50 41 53 53)  成功
        "FAIL"(46 41 49 4C)  失败
[4..7]  返回码 u32 小端（0=成功）
[8..]   数据
```

## 4. `0x28` 系统能力块解码（前 12 字节有效）

```
[0..1]  u16 小端  适配器瓦数（≥200 支持 BIOS 性能模式；≥280 支持 TGP/PPAB）
[2]               保留
[3]               热策略版本：0=V0, 1=V1, 2=V2(OMEN Max 2025+)
[4] bit0  软件风扇控制     bit1  狂暴/极限支持   bit2  极限已解锁
    bit3  BIOS 掌管控温    bit4  双字节 PL4
[5]               PL4 默认值
[6] bit0  BIOS 定义超频 (AMD)
[7]               显卡模式能力位域
[8]               默认 CPU 功耗上限（W，dGPU 负载时）
[9] 低半字节      LoadLine 支持档位数
    高半字节      LoadLine 默认值
[10] (bit0&bit1)==0b10  IR 传感器（两位组合！）  bit2 PCH  bit3 VR
[11] bit0 Fn+P 热键    bit1 Fn+F1 热键
```

**本机值**：适配器 280W、热策略 V1、feature=`0x01`、PL4 默认 200、`[8]`=55W、`[9]`=`0x00`、`[10]`=`0x00`。

## 5. `0x0F` 智能适配器解码（4 字节）

```
[0]      SmartAdapterStatus（0xFF/-1 = 未知）
[1] bit7 barrel 圆口支持
[2] ×5   USB-C 设计额定功率 W
[3] ×5   已连接适配器功率 W（0xFF = 未知）
```
**本机值**：`01 00 00 00` → status=1。

## 6. `0x29` 功率墙字节布局

```
TPP      { 0xFF, 0xFF, 0xFF, w }
PL1&PL2  { w,    w,    0xFF, 0xFF }
PL4      { 0xFF, 0xFF, w,    0xFF }
```
安全范围约 10–254 W。本机无读回命令，**改后无法校验**。

## 7. `0x21` / `0x22` GPU 功率

**读 `0x21`**（mode 2，4 字节）：`[cTGP, PPAB, dState, GPS]`
本机值：`01 01 01 57` → cTGP=1, PPAB=1, dState=1, **GPS=87**。

**写 `0x22`**（mode 2）：`[tgp, ppab, dstate, gps]`
- `dstate` HP 硬编码为 `1`，不是可调旋钮。
- `gps` 是 GPS 温度阈值（°C），出厂 87；发 0 也可（OmenCore 的选择）。
- **写后可用 `0x21` 回读校验**（本机已验证 GPS 会随之变化）。

## 8. `0x37`（多义，高风险）

| payload | 语义 |
|---|---|
| `[0]=0x00,[1]=0x0D, level` | 写 AC LoadLine |
| `[0]=0x00,[1]=0x0F, icc_lo, icc_hi` | 写 ICCMax（安培，LE） |
| `[0]=0x20, [2..3]=PL4 LE` | 写 PL4（双字节） |
| 4×0（V2 固件） | 读风扇档（OMEN Max 2025+） |

**本机未测**（无读回、影响稳定性和供电）。必须先读 `0x28[3]` 判断固件代际。

## 11. 返回码总表

| 返回 | 含义 | 处理 |
|---|---|---|
| `PASS` + `0x00` | 成功 | ✅ |
| `0x03` | 命令不可用（不支持） | 不要重试 |
| `0x05` | 缓冲区大小不符 | 检查 mode / Size |
| `0x06` | 参数无效 | 检查 payload |
| `AE_NOT_FOUND` | ACPI 方法不存在 | 检查方法路径 |
| `AE_AML_BUFFER_LIMIT` | 字段超缓冲区 | 检查 Command 空间/payload |
| `AE_AML_OPERAND_VALUE` | 参数值非法 | 常见于 Size=0 |
| `not called` | acpi_call 未执行 | payload 过大/格式错 |

## 13. 心跳 / 防锁（未实测，来自社区）

2023+ 机型 BIOS 有看门狗，长时间不通信会锁功耗/回退风扇：
- **心跳**：每 30–60s 发 `0x10`。
- **风扇倒计时**：自定义风扇约 120s 后回退，需每 60–90s 重发 `0x2E`。
- **退出/崩溃**：必须恢复自动模式。

## 14. Rust 实现要点

```rust
// 底层唯一入口（已有）
transport::wmaa(command, ctype, data, expected) -> Result<Vec<u8>, OmenError>

// mode 由 expected 自动推导
mode_for(expected): 0→1, 1..=4→2, 5..=128→3, ...

// 只读快捷
transport::read(command, ctype, expected)  // = wmaa(.., &[0,0,0,0], ..)
```

**铁律**：
1. Command 必须 u32 **小端**。
2. mode 必须匹配返回长度。
3. 读命令 Size=4；写命令 Size=数据长度。
4. `/proc/acpi/call` 读取必须用**大缓冲区一次读完**（否则返回空）。
5. 所有调用**串行加锁**。
6. 写操作前先想好恢复方案。

## 15. 固件内部实现（SSDT12 反汇编）

来自本机 DSDT/SSDT12 反汇编，解释了传输层为何如此工作。

### 15.1 方法调用链

```asl
Method (WMAA, 3, Serialized)      // 参数 3 个
{
    Acquire (MSMT, 0xFFFF)
    Local0 = WHCM (Arg1, Arg2)    // Arg0 被忽略！
    Release (MSMT)
    Return (Local0)
}
```

- `WMAA(Arg0, Arg1, Arg2)` 实际把 **`Arg1` 当 mode、`Arg2` 当 SECU 缓冲区**传给 `WHCM`。
- `Arg0` 固件**完全不用**（OmenMon 惯例传 `0x00`）。

### 15.2 `WHCM` 的输入解析

```asl
CreateDWordField (Arg1, Zero, SNIN)   // [0..3]  签名，须 == 0x55434553 ("SECU")
CreateDWordField (Arg1, 0x04, COMD)   // [4..7]  命令空间 (Command)
CreateDWordField (Arg1, 0x08, CMTP)   // [8..11] 命令类型 (CommandType)
CreateDWordField (Arg1, 0x0C, DASI)   // [12..15] 数据长度 (Size)
Local5 = DASI
CreateField (Arg1, 0x80, (Local5 * 0x08), DAIN)  // [16..] 数据区
```

`Switch (COMD)`：

| COMD 值 | 分支 |
|---|---|
| `1` | 读配置（`RDCF`） |
| `2` | 写配置（`WRCF`） |
| `0x00020002` | RTCD = 0x04 |
| `0x00020008` | 按 `CMTP` 分发到 `GCxx` 函数（性能/风扇/温度等） |
| 其它 | 落到默认 `RTCD = 0x03`（命令不可用） |

### 15.3 返回值组装

```asl
SNOU = 0x4C494146        // 初始 "FAIL"
RTCD = 0x02
... 成功时 ...
    RTCD = DerefOf (Local2 [Zero])      // 命令自身返回码
    if RTCD == 0:
        copy data...
        SNOU = 0x53534150               // "PASS"
Return (Local1)
```

### 15.4 ACPI 方法清单

`\_SB.WMID`（`_HID = PNP0C14`），定义于 **SSDT12**。存在的 HP 方法：`WMAA`、`WMBA`、`WMBH`、`WHCM`。**无 `WQAA`**。

## 16. `/proc/acpi/call` 读取坑（实测踩过）

`acpi_call` 内核模块的 read 实现在 **count（读取缓冲区）小于结果长度时会返回 0（空）**。

- Rust 的 `read_to_string()` 会先用 **32 字节**的小缓冲区探测，于是读到空串。
- `cat` 能成功，是因为它用 256 KiB 的大缓冲区。

**正确做法**：用足够大的缓冲区一次 `read()` 读完：

```rust
let mut raw = vec![0u8; 1 << 16];  // 64 KiB
let n = file.read(&mut raw)?;
let text = String::from_utf8_lossy(&raw[..n]);
```

该模块**每读一次就把结果重置为 "not called"**，只能读一次，读完要自己缓存。

## 17. `0x2F` 风扇表——格式未知

`0x2F` 返回 128 字节，首字节 = 风扇数量（本机 `0x02`），但其后数据的含义**无法确认**。

- 本机返回：`02 29 14 17 19 15 18 1a 16 19 1b 17 1a 1c 18 1b 1d 19 1c 1e 1a 1d 1f 1b 1e 20 1c 1f 21 1d 20 22 1e 21`
- 在任何 `(temp, pwm)` 配对方式下都**不构成单调曲线**，排除"温度-转速曲线表"的猜测。
- omencore、OmenSuperHub、OmenMon **三个项目都不读 0x2F**——它们用软件算法 + `SetFanLevel` 控制风扇。
- 结论：**0x2F 的数据格式未知，不应作为风扇曲线读取使用。**
